# North Carolina shadow mode — prepared, not scheduled

Proposed frequency: Friday, 05:17 America/New_York, once weekly. Neither workflow contains an active schedule. Separate human approval, a workflow change and the private shadow schedule gate are required before scheduling. NC is the only permitted state. Production publication, lifecycle adoption and archiving stay disabled.

The three-source pilot checks Apex applications, Chapel Hill Current Development and Raleigh Building Permits (supporting evidence only). This is not comprehensive statewide coverage. Each source receives a priority page and, when needed, a rotating backlog page, eight records each. Maximum: 48 source records, 16 government HTTP requests including retries, 120 worker seconds, 10 MB downloaded, 512 MB Node heap and six-minute Actions timeout. A retry resumes its saved source checkpoint; unfinished work is reported as partial, not a successful statewide update.

Expected HTTP use: approximately 9–12 requests per weekly run, often fewer with cached metadata and no backlog; hard ceiling 16. Four to five runs would reserve at most 64–80 requests per month against the existing monthly cap. No budget is increased automatically. The current remaining research allowance must be considered before any manual dispatch.

Robots policies are respected. Government schema and response shapes are checked before caching. Robots metadata is reused for 24 hours and API schemas for seven days; data requests use ETag/Last-Modified where supported. Cached responses have SHA-256 integrity checks, a 200 KB entry limit and 5 MB aggregate ceiling. Only reproducible response-cache entries older than 14 days are evicted. Findings and project history are preserved.

Every run stores private evidence, exact identity matches, duplicate suppression, application-scoped milestones, withheld status changes, potential expiration evidence, source errors and rejection reasons. GitHub receives aggregate counts only. The administrator dashboard retrieves detailed findings through an MFA-protected, backend-authorized RPC. No supporting permit can establish whole-project construction or completion. Missing sources cannot justify cancellation or archival. Ambiguous identities are withheld, never automatically merged.

The shadow database API has no publication, merge or archive operation. Its worker credentials cannot update production projects. All public data, approval policies, visibility rules and historical events remain unchanged. The individual administrator-confirmed milestone workflow is separate from shadow mode and requires a preview token bound to the current project, policy, history and activity.

Storage: persistent response cache is capped at 5 MB. Findings are capped at 20 KB each, giving an upper bound near 960 KB of findings for 48 entirely changed records per run, plus indexes/run metadata. Unchanged semantic findings are deduplicated. The existing database-size gate stops new runs before the Free quota; per-run reports estimate serialized finding/cache bytes, not exact PostgreSQL physical growth. Benchmark real recurring runs before assuming nationwide operation fits free limits.

Costs: no additional service, paid OCR, AI provider or paid runner is configured. Existing public GitHub Actions and Supabase Free resources are reused. This bounded pilot does not establish that 50-state maintenance fits free quotas. If limits are reached, checks stop and report unfinished work.

Manual regression validation uses the maintenance workflow's `guarded-shadow-audit` mode. It uses synthetic HTTP responses and the isolated audit schema in a transaction that is rolled back. It makes zero government requests, verifies guarded confirmation/deduplication/stale-policy rejection, cache reuse, outage reporting, forbidden-state/schedule rejection and unchanged production data.

## Research scope and deployment readiness

The workflow explicitly selects `structured-feeds` or `evidence-research`. The latter is now available only as an explicitly authorized manual trial. Its government development index, project-page/linked-document reader, secondary RSS/Atom reader, private evidence cache, request ledger and Supabase identity comparison are connected. Unattended evidence research remains blocked. A passing workflow is not evidence of complete source coverage: incomplete document or secondary retrieval is reported as partial.

The bounded PDF and government HTML extractors are reused by the manual worker. It records directly permitted documents and lists unrequested off-registry document links rather than bypassing restrictions. The current general web-search module reserves queries and accepts Codex-supplied findings; it remains separate from RSS-based research, is not an unattended search provider and still uses the legacy store interface. No paid search provider or AI inference is configured.

For full research, first register a small set of permitted official document indexes and credible secondary RSS/Atom feeds or public announcement pages. Use one jurisdiction per evidence run so robots, index retrieval, article/document downloads and retries all share the same 16-request ceiling. Rotate Apex, Chapel Hill and Raleigh across weekly slots rather than pretending all three received complete document verification every week. Government decisions remain primary; secondary reports are dated leads/corroboration and cannot alone establish an adopted approval, construction, cancellation or completion.

The private shadow API now permits narrowly scoped Chapel Hill official pages/files, Chapelboro news/feed URLs and UNC Health announcement/feed URLs as well as the three structured feeds. Worker credentials can still write only private research metadata. Do not bypass the URL allowlist or write projects via an owner credential. Additional jurisdictions and third-party planning portals need source-specific permission and extraction validation before registration.

Preserve exact source URL/identifier, response SHA-256, publication date when present, separate event date, check time, extraction page/quote, application versus parent-project scope, match method and withholding reason. A missing date stays null. HTTP 304 reuse is labeled explicitly, not presented as a freshly downloaded document. Identical verification observations do not create duplicate findings. Similar names or nearby pins produce review candidates, never automatic merges.

The standard PDF profile remains 2 MB/50 pages. The separately benchmarked 50 MB/200-page profile is not enabled by the shadow workflow: it cannot fit the current 10 MB total-download cap. Larger/scanned documents are deferred; there is no paid OCR fallback. A live planning-PDF extraction still needs demonstration on a permitted source; the first live run found no directly retrievable document on the inspected pages.

Proposed acceptance period: one manual real-source trial, then four NC-only weekly shadow observations after review and separate schedule authorization. Four runs require a worst-case reservation of 64 requests. On October 29, 2026, the verified remaining allowance was 23, sufficient for one 16-request reservation, not four. No new research requests were made while preparing this plan. Before activation, establish an explicit cumulative pilot allowance that cannot be replenished merely by a monthly counter reset; existing monthly/runtime/database gates remain additional safeguards.

Chapelboro was conservatively deferred by crawl-delay handling; the fallback UNC Health feed was accessible but its 12 current articles did not identify a qualifying development story. No planning PDF or secondary article was retrieved, so the research outcome is partial. Seven unreserved requests remain after the conservative 16-request reservation. No further live request was made for the cached parser/identity corrections or index-lead reconciliation.

Together with GIS matches these represent 14 distinct known identities, not 15 additional developments. Generic index excerpts cannot establish final decisions, construction or approval-expiration extensions. Detailed trial findings remain private; public GitHub summaries contain aggregates only.

Required acceptance evidence: exact/new/ambiguous identities against Supabase; adopted decision versus application/recommendation; unchanged evidence suppressed; new evidence version traceable; parent permit association; date conflict withheld; outages and budget exhaustion marked partial; no expired approval reset; no project/status/history/location/visibility or notification mutation; measured request/runtime/storage use. Only after human review should a schedule be added and its separate backend shadow gate opened. Production publication remains a separate, unapproved step.
